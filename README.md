# Restaurant Booking API

REST API для онлайн-бронирования столиков в ресторане. 
Позволяет создавать, просматривать, получать по id и отменять брони. 
Реализовано на FastAPI с асинхронным SQLAlchemy и SQLite.

## Стек технологий

- **Python 3.12** — основной язык разработки.
- **FastAPI** — веб-фреймворк для построения REST API.
- **Pydantic v2** — валидация данных и описание схем.
- **SQLAlchemy 2.0 (async)** — ORM для работы с базой данных.
- **SQLite** — лёгкая встраиваемая СУБД для хранения данных.
- **Uvicorn** — ASGI-сервер для запуска приложения.
- **pytest + httpx** — тестирование эндпоинтов.
- **Ruff** — линтер и инструмент для проверки стиля кода.
- **uv** — менеджер зависимостей и виртуальных окружений.
- **Docker** — контейнеризация приложения.

## Запуск локально

1. Клонируйте репозиторий:
   ```bash
   git clone <url>
   cd <project_dir>
   ```
   
2. Установите зависимости (uv сам создаст виртуальное окружение при необходимости):
    ```bash
   uv sync
    ```
   Если используете requirements.txt вместо pyproject.toml, выполните:
    ```bash
   uv pip install -r requirements.txt
    ```

3. Запустите сервер:
    ```bash
   uv run uvicorn app.main:app --reload
    ```
   
После запуска документация доступна по адресам:

Swagger UI: http://127.0.0.1:8000/docs

ReDoc: http://127.0.0.1:8000/redoc

## Запуск через Docker

1. Убедитесь, что Docker установлен и запущен.

2. Соберите образ и запустите контейнер:
    ```bash
   docker-compose up --build
    ```
   
3. API будет доступно по адресу http://localhost:8000.

Для остановки контейнера выполните docker-compose down.

Если нужно пересобрать образ после изменений, используйте docker-compose up --build.

## Тестирование

Для запуска тестов выполните:
```bash
    uv run pytest
```


## Основные решения

- SQLAlchemy 2.0 (async) + SQLite используются для хранения данных — это просто и достаточно для тестового задания, 
асинхронный режим позволяет эффективно работать с конкурентными запросами.

- Валидация бизнес-правил (формат телефона, диапазон дат, временные слоты) вынесена в отдельные функции 
и применяется через Pydantic-валидаторы, что отделяет правила от схем.

- Для обработки ошибок используются стандартные HTTPException, 
а конфликт слота обрабатывается отдельным исключением в сервисном слое и преобразуется в ответ 409.

- Логика доступа к данным вынесена в сервисный слой (services/booking_service.py), 
чтобы роуты оставались тонкими и легко тестировались.

- Для управления зависимостями и виртуальным окружением используется uv — 
это ускоряет установку пакетов и упрощает воспроизводимость окружения.
